ECOBLEND OS v2.0
MASTER SIDEBAR INFORMATION ARCHITECTURE + TYPOGRAPHY REFACTOR

PROJECT:
ECOBLEND OS / ecoblend.io

OBJECTIVE

Refactor the ECOBLEND OS left-hand navigation and typography into a coherent v2.0 product architecture before undertaking the wider colour, logo and visual-design implementation.

This task has two linked objectives:

A. INFORMATION ARCHITECTURE
Simplify the sidebar into a clear phase-oriented structure.

B. TYPOGRAPHY
Apply the approved ECOBLEND typography hierarchy from the controlled brand guideline and UI/UX design documentation.

This is NOT a backend refactor.

Do not alter application functionality, business logic, database structure, scoring, authentication, permissions, APIs or canonical routes unless specifically required to prevent a UI regression.

==================================================

/docs/design/Ecoblend-Brand-Guideline.pdf

The controlled brand typography system specifies:

PRIMARY BRAND TYPEFACE:
Avenir Next Condensed

APPROVED WEB ALTERNATIVE:
Prompt

APPROVED SECONDARY TYPEFACES:
Muli

==================================================
B2 — PRIMARY BRAND / DISPLAY TYPOGRAPHY
==================================================

Use:

Avenir Next Condensed

for ECOBLEND identity, display and navigation typography IF licensed webfont files are already available.

Use it for appropriate elements such as:

- major page titles
- sidebar section headings
- sidebar module labels
- product identity
- CORE WORKFLOW
- COMMAND CENTRE
- LAUNCH PHASE
- SCALE PHASE
- ADMINISTRATION
- dashboard section headings
- major card headings
- selected-state navigation
- controlled display typography

Visual characteristics should reflect the brand guideline:

- condensed form
- clean geometry
- clear weight contrast
- strong hierarchy
- restrained use
- professional rather than decorative


==================================================
B3 — AVENIR LICENSING SAFEGUARD
==================================================

Before using Avenir Next Condensed, determine whether valid webfont assets and licensing already exist in the project.

DO NOT:

- download unofficial Avenir font files
- scrape Avenir files
- use unlicensed font copies
- convert desktop fonts into webfonts without confirming licensing

If licensed Avenir webfonts are not available, use the brand-approved alternative:

Prompt

The display font stack should therefore behave approximately as:

"Avenir Next Condensed", "Prompt", sans-serif

==================================================
B8 — CASING RULES
==================================================

Use UPPERCASE selectively for:

- high-level sidebar groups
- compact metadata labels
- controlled navigation headers

Use Title Case or sentence case for:

- modules
- submodules
- page titles
- cards
- descriptions
- instructions
- evidence records

Do not render long-form content in uppercase.


==================================================
B9 — CENTRAL DESIGN TOKENS
==================================================

Create reusable typography tokens.

For example:

--font-brand: "Avenir Next Condensed", "Prompt", sans-serif;
--font-interface: "Lato", sans-serif;
--font-data: "Lato", sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", Consolas, monospace;

Create semantic type tokens such as:

--text-display
--text-h1
--text-h2
--text-nav-section
--text-nav-item
--text-body
--text-data
--text-meta
--text-score

Use the project's existing CSS/Tailwind/design-token architecture where possible rather than creating a competing styling system.

Do not scatter hard-coded font declarations across individual components.
