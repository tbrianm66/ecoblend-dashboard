# 4. Lean Startup Principles to Embed

The module must apply these Lean Startup principles:

## Validated learning

Progress should not be measured by the amount of planning completed. Progress should be measured by whether the venture has learned something empirically about customer value, pricing, growth, delivery, or business model viability.

## Build–Measure–Learn

Every model assumption should be capable of being tested through an experiment.

## Value hypothesis

The system must test whether the proposed solution creates real value for the customer.

## Growth hypothesis

The system must test how the venture might acquire, retain, and grow its customer base.

## MVP discipline

The module should help define the minimum business model test before R&D builds a full solution.

## Innovation accounting

The module should define measurable learning milestones and actionable metrics.

## Pivot or persevere

If evidence contradicts the proposition or business model, the system should recommend pivoting the customer segment, problem, value proposition, revenue model, pricing model, channel, or delivery model.

# 16. Model Readiness Decision

Create a Model Readiness Decision page.

## Purpose

This page should determine whether the venture is ready to proceed to R&D Hub / MVP definition.

## Readiness Score

Calculate:

Proposition & Model Readiness Score =
Value Proposition Quality Score × 20%

* Customer Job Clarity Score × 15%
* Business Model Readiness Score × 20%
* Revenue Model Evidence Score × 20%
* Unit Economics Confidence Score × 15%
* inverse Business Model Risk Score × 10%

Output categories:

* 0–39 = Not ready
* 40–59 = Needs more model validation
* 60–79 = Ready for limited MVP definition
* 80–100 = Strong proposition/model readiness

## Decision logic

If score is below 40:

* Recommend: do not proceed to MVP build
* Required action: revise proposition or business model

If score is 40–59:

* Recommend: run more proposition, revenue, pricing, or unit economics tests

If score is 60–79:

* Recommend: proceed to limited MVP definition with unresolved assumptions listed

If score is 80–100:

* Recommend: proceed to R&D Hub and define MVP experiment

If WTP Score is below 60:

* Override recommendation: strengthen commercial validation before MVP build

If no customer job is defined:

* Override recommendation: define Jobs-to-be-Done before MVP build

If no measurable customer outcome exists:

* Override recommendation: value proposition is not testable

If business model has critical risks:

* Override recommendation: mitigate model risks before stage progression

## Required actions

Allow the user to:

* Approve model readiness
* Request more evidence
* Create revenue model test
* Create pricing experiment
* Create Lean experiment
* Update Lean Canvas
* Create pivot log
* Send to R&D Hub
* Send alert to Command Centre

* It prevents premature progression to MVP build when WTP, customer job, measurable outcome, or business model evidence is weak.
* It feeds Command Centre, R&D Hub, Brand & GTM, and Market Risk Log.
* Seed data demonstrates BEBUS, ECOCOMP, REAL, and TONE.

# 23. Critical Failure Modes to Avoid

Avoid these mistakes:

1. **Static business planning**
   Do not build this as a business-plan document generator. Build it as an evidence-based proposition and model validation system.

2. **Solution bias**
   Do not let users define the solution before the customer job, pain, gain, and measurable outcome are clear.

3. **Generic value propositions**
   Reject or warn against vague claims such as “AI-powered”, “sustainable”, “innovative”, or “data-driven” unless they are linked to measurable customer value.

4. **Disconnected Lean Canvas**
   The Lean Canvas must link to hypotheses and evidence, not sit as an isolated template.

5. **False commercial confidence**
   Do not let revenue model confidence exceed WTP evidence.

6. **Ignoring unit economics**
   Commercial interest is not enough if delivery cost, margin, CAC, LTV, or payback assumptions are structurally weak.

7. **Premature MVP build**
   The system must block or warn against moving to R&D Hub if the proposition and model are not sufficiently validated.

8. **No pivot memory**
   Proposition and model changes must be logged with evidence triggers.

9. **No cross-module integration**
   This module must exchange data with Venture Intake, Discovery & Market, WTP Assessment, Command Centre, Market Risk Log, R&D Hub, and Brand & GTM.

10. **Duplicate data models**
    Reuse existing venture, hypothesis, evidence, experiment, decision, pivot, and Lean Canvas structures wherever possible.
