# 7. Scoring Logic

Create reusable scoring utilities.

## Canvas Completeness Score

Calculate:

Canvas Completeness Score =
Completed Blocks / 11 × 100

Completed means the block has non-empty content.

Interpretation:

* 0–39 = Incomplete
* 40–69 = Partially complete
* 70–89 = Complete but evidence review required
* 90–100 = Structurally complete

---

## Canvas Evidence Confidence Score

For each block, calculate block confidence:

Block Confidence =
Hypothesis Link Score × 25%

* Evidence Link Score × 35%
* Evidence Strength Score × 25%
* No Contradiction Score × 15%

Where:

Hypothesis Link Score:

* Has linked hypothesis = 100
* No linked hypothesis = 0

Evidence Link Score:

* Has linked evidence = 100
* No linked evidence = 0

Evidence Strength Score:

* strong_evidence = 100
* moderate_evidence = 70
* weak_evidence = 40
* no_evidence = 0
* contradicted = 0

No Contradiction Score:

* no contradiction = 100
* contradiction exists = 0

Canvas Evidence Confidence Score =
Average of all block confidence scores

---

## Model Readiness Score

Calculate:

Model Readiness Score =
Canvas Completeness Score × 30%

* Canvas Evidence Confidence Score × 40%
* WTP Score × 15%
* Unit Economics Confidence Score × 10%
* inverse Business Model Risk Score × 5%

If WTP Score is missing, cap Model Readiness Score at 70.

If Unique Value Proposition has no measurable customer outcome, cap score at 60.

If Revenue Streams has no WTP evidence, cap score at 60.

If Problem has no customer discovery evidence, cap score at 50.

If more than three blocks are contradicted, cap score at 40.

Interpretation:

* 0–39 = Not ready
* 40–59 = Needs evidence
* 60–79 = Ready for limited MVP definition
* 80–100 = Strong model readiness

# 11. Auto-Risk and Alert Logic

The Lean Canvas module should create risks and alerts automatically.

## Auto-create risks

Create a Business Model Risk or Market Risk when:

* Problem block has no customer discovery evidence
* Customer Segments block has no linked segment hypothesis
* UVP block has no measurable customer outcome
* Revenue Streams block has no WTP evidence
* Cost Structure block is blank
* Key Metrics block contains vanity metrics
* Unfair Advantage block is generic
* More than three blocks have weak or no evidence
* Any block is contradicted by evidence
* Model Readiness Score is below 50

## Auto-create Command Centre alerts

Create a command alert when:

* Venture is moved to R&D Hub but Model Readiness Score is below 60
* Venture is moved to MVP Validation but Lean Canvas is incomplete
* Revenue Streams is unsupported by WTP evidence
* Problem is unsupported by customer discovery evidence
* A canvas change suggests a pivot but no pivot log exists
* Canvas has not been updated after major WTP or customer discovery learning

Alert severity:

* Critical = stage progression attempted with weak canvas evidence
* High = core block missing or contradicted
* Medium = incomplete evidence links
* Low = canvas requires routine update

# 12. Integration With Stage-Gate Logic

The Lean Canvas should influence whether a venture can progress from:

**Proposition & Model → R&D Hub → MVP Validation**

Stage-gate rule:

A venture should not progress to R&D Hub unless:

* Canvas Completeness Score is 70 or above
* Model Readiness Score is 60 or above
* Problem block has customer discovery evidence
* Customer Segments block has linked hypothesis
* Unique Value Proposition has measurable customer outcome
* Revenue Streams has WTP evidence or an explicit WTP experiment is active
* Key Metrics are actionable
* No critical canvas risks are unresolved

If these requirements are not met, show:

“Lean Canvas is not ready to support MVP definition.”

# 17. Critical Failure Modes to Avoid

Avoid these mistakes:

1. **Static canvas theatre**
   Do not create a polished canvas that is disconnected from evidence.

2. **No version control**
   Canvas changes must be tracked over time.

3. **No evidence links**
   A Lean Canvas block should not be treated as validated unless evidence supports it.

4. **No pivot memory**
   Major changes must prompt pivot logging.

5. **Generic business model language**
   Warn against vague UVP, channel, metric, and unfair advantage statements.

6. **False readiness**
   Do not allow the venture to appear ready for MVP build when customer, problem, revenue, or WTP evidence is missing.

7. **Duplicated data structures**
   Reuse existing venture, hypothesis, evidence, experiment, and decision records.

8. **Overbuilding export**
   Start with markdown/copy summary before PDF or deck generation.

9. **No cross-module integration**
   The canvas must feed Command Centre, Proposition & Model readiness, R&D Hub, Brand & GTM, and Market Risk Log.

10. **Ignoring EcoBLEND data moat**
    For relevant ventures, the Unfair Advantage block should explicitly support proprietary technical data, repeatability knowledge, trade secrets, controlled access, and scalable product intelligence.
