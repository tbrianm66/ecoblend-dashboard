This looks like a state/navigation persistence bug, not a database issue by default.

From the screenshot, the app is probably resetting the active route/state to:

Command Centre → Portfolio Overview

whenever a sub-folder/module is opened. The common causes are:

1. The sidebar click is updating local UI state, but the route is not persisted.
    On render/refresh/error, the app falls back to the default module.
2. A runtime error occurs inside the selected sub-module component.
    React then remounts or redirects to the default dashboard.
3. The active module/submodule is stored in component state rather than URL params or global state.
    On any re-render, mobile resize, or data refresh, it resets.
4. The database query for that sub-folder returns null/undefined.
    The app may interpret missing content as “go back to default”.
5. There may be a mobile layout/sidebar bug.
    The screenshot shows the sidebar taking up too much of the viewport, suggesting responsive state and navigation state may be interfering.

Replit Debug Prompt: Module Sub-Folder Crash / Navigation Reset

I need you to audit and fix a navigation/state bug in the EcoBlend VBS Analytics Dashboard app.

Problem

Every time I open a sub-folder inside any module, the app crashes or resets back to:

Command Centre → Portfolio Overview

The expected behaviour is that when I open any module or sub-folder, the selected module should stay open and the correct sub-folder content should render.

Current visible issue

The app appears to default back to the command centre portfolio dashboard instead of preserving the selected module/sub-folder. This occurs when navigating into sub-folders inside the sidebar modules.

Please investigate the root cause across frontend routing, sidebar state, component rendering, and database/content loading.
